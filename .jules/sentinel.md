## 2024-05-14 - IP Spoofing via Unvalidated Header
**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-06-17 - SSRF via Unvalidated Protocol Header and Host Header Injection Risks
**Vulnerability:** The API server's clerk proxy middleware directly extracted the `x-forwarded-proto` header value and blindly used it to construct a downstream URL. This allowed an attacker to inject arbitrary URI schemes (e.g., `javascript://`, `ftp://`) leading to SSRF or scheme injection. Furthermore, attempting to "fix" host resolution by manually extracting `x-forwarded-host` bypassed Express's `trust proxy` mechanism, introducing a critical Host Header Injection vulnerability.
**Learning:** Directly interpolating user-controlled headers (like `x-forwarded-proto` or `x-forwarded-host`) into URLs is highly dangerous. While `req.protocol` might seem like a framework-level solution, relying on it blindly can cause application regressions if `trust proxy` is disabled or misconfigured. In addition, using `req.get("host")` properly respects Express's proxy configuration (when set) and avoids the pitfalls of manually parsing potentially spoofed forwarding headers.
**Prevention:** To prevent protocol spoofing, explicitly validate and sanitize protocol headers against a strict allowlist (e.g., `header === 'http' ? 'http' : 'https'`). For host resolution, rely on framework-provided methods like `req.get("host")` rather than manually extracting `x-forwarded-host`, and ensure the application's `trust proxy` setting is properly configured for the deployment environment.
