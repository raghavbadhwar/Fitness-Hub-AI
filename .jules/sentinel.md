## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2026-07-19 - SSRF and DoS in Raw Node.js Servers via Unvalidated Headers

**Vulnerability:** A raw Node.js server (`serve.js`) blindly trusted the `x-forwarded-host` header to generate dynamic URLs in HTML responses, allowing Server-Side Request Forgery (SSRF) and Host Header Injection. In addition, `new URL()` was instantiated using `req.headers.host` without a fallback, leading to `TypeError: Invalid URL` exceptions and server crashes (Denial of Service) when requests lacked a Host header.
**Learning:** Raw Node.js servers (unlike Express applications with `trust proxy` configured) lack built-in proxy trust validation. Parsing client-controlled proxy headers like `x-forwarded-host` without validation is inherently insecure and can lead to URL spoofing. Furthermore, `req.headers.host` can be undefined, and passing an undefined base to the strict `URL` constructor causes application-crashing exceptions.
**Prevention:** Never blindly parse `x-forwarded-host` in un-trusted proxy environments; use the standard `host` header instead. Always provide a safe fallback string (e.g., `req.headers.host || 'localhost'`) when passing potentially undefined header values as the base to `new URL()` to prevent application crashes.
