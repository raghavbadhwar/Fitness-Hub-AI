## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-05-14 - IP Spoofing & Host Header Injection via Unvalidated Header
**Vulnerability:** The API server's clerk proxy middleware directly read `req.headers["x-forwarded-proto"]` and `req.headers.host` to determine the request protocol and host, without relying on Express's secure proxy mechanisms or native accessors. This could allow an attacker to spoof the proxy protocol or inject malicious `host` headers, potentially enabling Server-Side Request Forgery (SSRF) or cache poisoning by controlling the URL used by the internal proxy.
**Learning:** In Express proxy middlewares, relying on unvalidated `x-forwarded-*` headers directly bypasses the framework's `trust proxy` protections, which are responsible for securely extracting the original protocol from trusted upstream load balancers.
**Prevention:** In environments where `trust proxy` is enabled, always use `req.protocol` instead of parsing `req.headers["x-forwarded-proto"]`. While `req.hostname` safely resolves the host, proxy middlewares for local development require the port to be preserved. Therefore, securely extract the host with the port intact by prioritizing `req.get('host')` (which is standard and safer than raw header objects), or explicitly fallback to `req.headers.host`.
