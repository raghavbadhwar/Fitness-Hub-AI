## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-07-09 - Protocol Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-proto` header from incoming requests to determine the protocol. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-proto` header to bypass security restrictions or cause unexpected behavior when reconstructing the proxy URL.
**Learning:** Manually parsing `x-forwarded-proto` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy, the framework needs to be configured using `trust proxy` to securely parse these headers. Using `req.protocol` securely handles this. For the host, `req.hostname` strips the port, so to preserve the port for local dev, we should use `req.get("host")` while continuing to rely on `req.protocol` to prevent protocol spoofing.
**Prevention:** Always use `req.protocol` in Express instead of reading `req.headers["x-forwarded-proto"]` directly. Ensure the application's `trust proxy` setting is correctly configured. When resolving the host for URLs, use `req.get("host")` if preserving the port is required, instead of blindly trusting `req.headers["x-forwarded-host"]` or parsing it manually.
