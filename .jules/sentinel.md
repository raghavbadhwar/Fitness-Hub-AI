## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-07-04 - Protocol and Host Spoofing in Proxy Middleware

**Vulnerability:** The proxy middleware manually parsed `req.headers["x-forwarded-proto"]` and `req.headers.host` to construct URLs. Because these headers are client-controlled and not automatically sanitized by the framework unless processed through Express's specific getters (like `req.protocol` and `req.hostname`), a malicious actor could send spoofed headers to bypass protections or execute Server-Side Request Forgery (SSRF) or cache poisoning attacks.
**Learning:** Directly reading raw proxy headers (`x-forwarded-*` or `host`) bypasses Express's `trust proxy` mechanism. In Express, `req.hostname` respects `trust proxy` but strips the port, while `req.get('host')` keeps the port but ignores `trust proxy`. To securely construct full URLs behind a trusted proxy while preserving the port, you must safely validate `x-forwarded-host` against the trusted `req.hostname`.
**Prevention:** Always use `req.protocol` and `req.hostname` (or securely validate `x-forwarded-host` against `req.hostname` using `URL` parser) instead of manually reading headers. When using `http-proxy-middleware`, cast `req` to an Express `Request` to access these secure properties.
