## 2024-05-24 - [Prevent Protocol and Host Spoofing in Proxy Middleware]
**Vulnerability:** The clerk proxy middleware manually parsed `x-forwarded-proto` and `host` headers from the raw request, making it susceptible to host header injection and protocol spoofing if a malicious actor controls those headers.
**Learning:** Manually reading `req.headers["x-forwarded-proto"]` and `req.headers.host` bypasses Express's internal security mechanics designed to handle proxies securely. Express provides `req.protocol` which correctly respect the application's `trust proxy` settings. For the host header, relying solely on `req.headers.host` is insufficient; it requires basic regex validation (`/[^\w.:-]/`) to ensure it doesn't contain injected malicious characters, and fallback to `localhost` if it does.
**Prevention:** Always use `req.protocol` instead of manually reading `x-forwarded-proto`. Always sanitize the `host` header using regex validation when proxying requests based on it.
