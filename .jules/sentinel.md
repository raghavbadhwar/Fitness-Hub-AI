## 2024-05-14 - IP Spoofing via Unvalidated Header
**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-05-15 - Protocol Spoofing via Unvalidated Header
**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-proto` header from incoming requests to determine the protocol. Because this header is client-controlled, a malicious actor could send a spoofed protocol header to bypass security checks or cause the proxy to construct malicious URLs.
**Learning:** Manually parsing `x-forwarded-proto` directly from `req.headers` skips the framework's secure handling of proxy trust, similar to IP spoofing. Express's built-in `req.protocol` securely respects the `trust proxy` configuration and determines the correct protocol from the first trusted proxy.
**Prevention:** Always use `req.protocol` in Express to securely determine the request protocol, rather than manually extracting it from `req.headers['x-forwarded-proto']`. Ensure a fallback (e.g., `req.protocol || "https"`) is provided for environments where `trust proxy` might be unconfigured.

## 2024-05-15 - Host Header Injection via Unvalidated Host
**Vulnerability:** The API server's clerk proxy middleware directly accessed the raw `req.headers.host` to construct proxy URLs. This is vulnerable to Host Header Injection because the raw `Host` header can be manipulated by an attacker to cause the application to generate unintended links or bypass access controls.
**Learning:** Directly accessing `req.headers.host` bypasses Express's internal parsing and formatting. Express provides `req.get('host')` which securely retrieves the `Host` header. While `req.get('host')` is still the unvalidated header and relying solely on it is insufficient to completely prevent host header injection without explicit host validation, it is the framework-standard and slightly safer way to access the header compared to direct property access.
**Prevention:** Avoid direct access to `req.headers.host`. Use `req.get('host')` instead. For critical security constructs, the resolved host should be validated against a known whitelist of allowed hosts.
