## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## $(date +%Y-%m-%d) - SSRF and Host Header Injection via Unvalidated Host

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `host` and `x-forwarded-host` headers from incoming requests to construct proxy URLs. Because these headers are client-controlled, a malicious actor could send a spoofed `x-forwarded-host` or `host` header to manipulate the proxy URL, potentially leading to Server-Side Request Forgery (SSRF) or routing bypasses.
**Learning:** Manually parsing host-related headers directly from `req.headers` skips the framework's secure handling of proxy trust and can lead to Host Header Injection. When an Express application is running behind a trusted proxy, the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse these headers.
**Prevention:** Always use `req.hostname` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers.host` or `req.headers["x-forwarded-host"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.hostname` returns the true hostname instead of a spoofed one. For the port, securely extract it or fallback to `req.get('host')` only if the hostname is validated.
