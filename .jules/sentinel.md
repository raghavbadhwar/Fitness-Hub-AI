## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-05-24 - [CRITICAL] Prevent DoS from Invalid Host Headers via new URL()

**Vulnerability:** The Expo static build server `artifacts/gymapp/server/serve.js` was passing `req.headers.host` directly into `new URL(req.url, \`http://\${req.headers.host}\`)`without validating the host header or wrapping it in a try-catch block. An attacker could send a request with an empty, malformed (e.g.,`%foo`), or array-type Host header to trigger an uncaught `TypeError: Invalid URL`, crashing the Node.js process and causing a Denial of Service (DoS). Additionally, `x-forwarded-proto`and`x-forwarded-host`headers were directly used as strings without handling potential comma-separated lists from chained proxies.
**Learning:** Blindly trusting`req.headers.host`or proxy headers when constructing URLs can lead to uncaught exceptions in Node.js. Server configurations should anticipate invalid headers, fallback to a default like "localhost", and catch URL parsing errors. Chained proxies can also inject multiple values into headers, requiring a`.split(",")[0].trim()`approach.
**Prevention:** Always validate or sanitize headers like`host`and`x-forwarded-proto`before using them. Ensure that`new URL()`operations using untrusted inputs are wrapped in`try-catch`blocks and respond with 400 Bad Request on failure. When parsing`x-forwarded-\*` headers, account for potential array-like or comma-separated lists.
