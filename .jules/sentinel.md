## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-05-15 - Unhandled Exception DoS via Invalid URL Parsing

**Vulnerability:** The raw Node.js standalone server crashed due to an unhandled exception (`TypeError: Invalid URL`) when an invalid `host` header (e.g. `%%invalid%%`) was passed into `new URL(req.url, 'http://' + req.headers.host)`. Additionally, the server used `req.headers['x-forwarded-host']` without any trust proxy validation, making it vulnerable to Host Header Injection and potentially SSRF, and failed to handle comma-separated values for proxy headers.
**Learning:** `new URL()` in Node.js throws an error on malformed URLs. If this is not wrapped in a `try-catch`, any malicious request providing an invalid `Host` header can instantly crash the server (Denial of Service). Furthermore, blindly trusting `x-forwarded-*` headers in a standalone Node.js server (which lacks Express's `trust proxy` mechanism) bypasses security, and proxy headers may contain comma-separated values that must be handled appropriately.
**Prevention:** Always wrap `new URL()` instantiation in a `try-catch` block when passing potentially malformed or client-controlled inputs (like headers). In raw Node.js environments, strictly use the standard `host` header unless explicit custom parsing logic mimicking `trust proxy` is implemented, and safely split/trim proxy headers before using them to prevent parsing errors.
