## 2024-05-14 - Protocol Spoofing & SSRF via Unvalidated Header
**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-proto` and `host` headers from incoming requests to determine the protocol and host for the `Clerk-Proxy-Url`. Because these headers are client-controlled, a malicious actor could send spoofed headers to bypass security controls or perform Server-Side Request Forgery (SSRF).
**Learning:** Manually parsing headers like `x-forwarded-proto` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy, the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse headers, starting from the most trusted proxy backwards. Additionally, using `req.hostname` strips the port, breaking local dev setups, while `req.get("host")` preserves it.
**Prevention:** Always use `req.protocol` in Express to securely evaluate the protocol. Use `req.get("host")` (instead of `req.headers.host`) to safely evaluate the host while keeping ports intact for local development. Make sure the proxy middleware is properly configured to respect proxy trust rules to avoid SSRF issues and protocol spoofing.
