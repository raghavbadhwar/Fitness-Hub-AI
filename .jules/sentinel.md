## 2024-05-14 - IP Spoofing via Unvalidated Header
**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2025-02-20 - Protocol Spoofing & Host Header Injection via Unvalidated Headers
**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-proto` and `host` headers from incoming requests to determine the protocol and proxy URL. Because these headers are client-controlled and were parsed directly from the raw request, malicious actors could send spoofed `x-forwarded-proto` or `host` headers to bypass intended proxy routing or inject a malicious host header in the proxy request.
**Learning:** Manually parsing `x-forwarded-proto` directly from `req.headers` skips Express's secure handling of proxy trust. Like `req.ip`, when an Express application runs behind a trusted proxy, it needs to be configured with `app.set("trust proxy", ...)` to securely parse protocol headers. Additionally, using raw `req.headers.host` does not align with Express's `req.get('host')` fallback and potential sanitization patterns.
**Prevention:** Always use Express's built-in secure accessors like `req.protocol` and `req.get("host")` rather than reading raw headers directly from `req.headers["x-forwarded-proto"]` or `req.headers.host`. When working with `http-proxy-middleware`, the `req` object inside `on.proxyReq` might need to be cast to `express.Request` to access these secure properties securely. Ensure the application's `trust proxy` setting is configured correctly for the deployment environment.
