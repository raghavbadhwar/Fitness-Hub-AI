## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-05-15 - Uncaught Exception in URL Parsing (DoS) and Host Header Injection

**Vulnerability:** The raw Node.js static server was vulnerable to Denial of Service (DoS) and Host Header Injection. Constructing `new URL()` directly from unvalidated, client-controlled headers like `req.headers.host` would throw an uncaught `TypeError: Invalid URL` if the header contained invalid characters (e.g., `invalid:port:%%%`), crashing the entire server. Additionally, blindly trusting `x-forwarded-host` bypassed proxy trust mechanisms.
**Learning:** When using raw Node.js without a framework that handles proxy trust and safe request parsing, you must never blindly trust `x-forwarded-host`. Furthermore, any operation that parses external input (like `new URL()`) must be wrapped in a `try-catch` block, because uncaught synchronous exceptions in the request handler will bring down the Node.js process.
**Prevention:** Always use `req.headers.host` directly in raw servers instead of `x-forwarded-host`. Always wrap `new URL()` and similar strict parsers in a `try-catch` block when processing user-controlled input like headers, responding with a `400 Bad Request` on failure instead of crashing.
