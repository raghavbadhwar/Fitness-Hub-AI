## 2025-02-27 - [Sentinel] Fix manual X-Forwarded-Proto parsing in Clerk Proxy Middleware
**Vulnerability:** The `clerkProxyMiddleware.ts` was manually parsing `req.headers["x-forwarded-proto"]` instead of using the secure `expressReq.protocol`. Manual parsing allows attackers to spoof the protocol header regardless of whether the application is securely configured behind a trusted proxy, opening up risks of protocol spoofing in environments where proxy chains should be strictly evaluated.
**Learning:** Bypassing Express's built-in `trust proxy` mechanism by directly reading proxy headers (like `x-forwarded-proto`) exposes the application to header spoofing. When an Express application is running behind a trusted proxy, the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse forwarded headers starting from the most trusted proxy backwards. `req.protocol` securely respects this configuration.
**Prevention:** Always use `req.protocol` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-proto"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.protocol` correctly resolves the protocol string.
