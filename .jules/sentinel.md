## 2024-05-14 - IP Spoofing via Unvalidated Header

**Vulnerability:** The API server's clerk proxy middleware manually parsed the `x-forwarded-for` header from incoming requests to determine the client IP address. Because this header is client-controlled, a malicious actor could send a spoofed `x-forwarded-for` header to bypass IP-based logging, rate limiting, or to mask their true origin in the proxy request.
**Learning:** Manually parsing `x-forwarded-for` directly from `req.headers` skips the framework's secure handling of proxy trust. When an Express application is running behind a trusted proxy (like a load balancer or ingress controller), the framework needs to be explicitly configured using `app.set("trust proxy", ...)` to securely parse the XFF header, starting from the most trusted proxy backwards.
**Prevention:** Always use `req.ip` in Express (or the equivalent secure accessor in other frameworks) rather than reading `req.headers["x-forwarded-for"]` directly. Ensure the application's `trust proxy` setting is correctly configured for the deployment environment so that `req.ip` returns the true client IP instead of a spoofed or intermediate proxy IP.

## 2024-06-15 - Host Header Injection / SSRF in Proxy Middleware

**Vulnerability:** The `clerkProxyMiddleware` manually parsed `req.headers["x-forwarded-proto"]` and `req.headers.host` directly to construct the proxy URL. This bypasses Express's built-in `trust proxy` mechanism, allowing a malicious client to spoof the protocol and host via forged headers, potentially leading to Host Header Injection or SSRF vulnerabilities by redirecting the Clerk proxy requests to an attacker-controlled domain.
**Learning:** Blindly trusting `x-forwarded-*` headers or the `Host` header circumvents framework-level proxy trust configurations. When building URLs in an Express application behind a proxy, you should rely on `req.protocol` and `req.hostname`, which securely evaluate the headers according to the application's `trust proxy` setting. Additionally, if the port from `req.get("host")` must be preserved, it should be done carefully by comparing the securely derived `req.hostname` with parsed proxy headers (`x-forwarded-host`) to prevent mixing trusted internal logic with untrusted input.
**Prevention:** Always cast the request object to Express `Request` and use `req.protocol` and `req.hostname` when determining the requested origin. If port preservation is necessary, securely parse `req.get("x-forwarded-host")` or `req.get("host")` and strictly validate the extracted hostname against `req.hostname` before using it, and handle potential URL parsing exceptions (e.g., due to comma-separated proxy chains) gracefully to prevent DoS.
