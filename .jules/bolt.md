## 2024-05-20 - Promise Caching & Array Optimizations
**Learning:** In the `admin` workspace dashboard, calculating statistics used multiple `O(N)` array traversals (`.filter`, `.reduce`, `.map`) which unnecessarily increases memory allocations and CPU cycles. Furthermore, fetching the active member count from Clerk is expensive and susceptible to cache stampedes under concurrent load if only the resolved value is cached.
**Action:** Implement single-pass `O(N)` loops and pre-initialized hash maps to compute all aggregates simultaneously. Use Promise caching (storing `Promise<number>` instead of the resolved value) with a 5-minute TTL to handle concurrent dashboard requests safely, ensuring to cache the original promise and attach `.catch(() => cache.delete(key))` to handle invalidation correctly.
